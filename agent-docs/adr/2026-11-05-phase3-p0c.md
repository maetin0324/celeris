# ADR 2026-11-05: long-horizon ベンチ v2 の採点（公開の契約と保護領域の検査 script）（phase3 P0-C）

- 状態: 採用・実装済み。
- 関係: [phase3 の不変条件](2026-11-05-phase3-achievement-invariants.md)（I5・I6・I12、K13〜K16・K23・K42）、[A9 findings](2026-11-05-a9-llm-pilot-findings.md) の D2、[long-horizon ベンチ](2026-11-04-long-horizon-bench.md) の D4・D5・付記 A8 の 4。

## 結論
- 固定文字列の sha256 一致（`oracle/<case>/hidden/expected.json`）を消した。Outcome の到達は、保護領域の検査 script `tests/fixtures/long-horizon/grader/check_outcome.py` の exit code（0 = 到達、1 = 未到達、それ以外 = 観測できない）だけで決まる。
- 契約は公開する。全 10 課題の `public/<case>/repo-seed/README.md` の「成果の契約」と `case.json` の acceptance に書いた。`out/<id>.txt` に 4 欄（`case`・`outcome`・`status`=`verified`・`evidence`=sha256(`minichunk <case> <id> chunk`)）を、行の形（`:`・`：`・`=`、順序・空白・他の行は自由）か JSON の object で書けば合格する。
- `bench_version` を 2 に上げ、canary と trial salt を作り直した。v1 の raw（`2026-11-04-long-horizon/a8b/replay`・`a9/{llm,stub,virtual}`）は改変しない。v2 の採点器は版の不一致で v1 の raw を拒む。

## 決定
1. **script は 1 本で、課題ごとに置かない**。A9 findings D2 は `oracle/<case>/hidden/check-<id>.sh` を挙げたが、契約は全課題で同じ形なので、22 本の写しは作らない。課題と Outcome は引数で渡す。置き場は `public/` とも `oracle/` の台本とも別の `grader/` で、`oracle/MANIFEST.sha256` に hash を載せる。
2. **grader の隔離**: `Grader::open` は script の hash を manifest と照合し、違えば採点しない。実行は `env -i`・`python3 -I -S`・空の一時 dir を cwd にした子 process（`grade_runner::ProcessRunner`、上限 30 秒）。script は木の `out/<id>.txt` だけを `lstat`・`O_NOFOLLOW` で読み、symlink・dir・64 KiB 超・UTF-8 でない file を未到達にする。木のコードを実行も import もしない。木と fixtures が重なる配置は Err。
3. **leakage**: 採点器は試行の木を走査し、script の印（`GRADER_MARKER`）・script の hash・canary・trial salt・oracle の file 名が現れた試行を `leak_detected` にして分母から外す。real daemon の driver は試行の home 全体（run の記録・DB を含む）を同じ値で走査し、facts の `leak_hits` に書く。replay の gate は `leak_detected` が 0 であることを要する。
4. **公開の自己検査**: `minichunk.py check <case> <id>` を公開の側に置いた（P0-E が root の command check に使える）。木の中のこの実装は worker が書き換えうるので、採点には使わない。採点は保護領域の script だけ。
5. **I12**: facts に `controller_achieved`（案件の `project_controller_state.phase` が `achieved`）を足した。`achieved_at` は replay では台本の木が揃った時刻で腕によらないので、controller の主張に使わない。採点は試行ごとに `agreement`（`controller_achieved`・`oracle_verdict`・`mismatch`・`oracle_pass_without_achieved`）を出し、summary に `achieved_oracle_mismatch` を数える。replay の gate は不一致 0 を要する。
6. **v1 の保存**: v1 の fixture は `agent-docs/progress/2026-11-05-phase3/p0c/v1-fixtures/` に写し、v1 の raw 256 file の sha256 を `p0c/v1-raw.sha256` に固定して試験で照合する。実 LLM の v2 raw の既定の置き場は phase3 の進捗 dir の下の `llm-v2/`（まだ無い。P0-F が作る）。`long-horizon-pilot-llm.sh` は `2026-11-04-long-horizon/` の下への出力を拒む（前は既定で `a9/llm` を消して書き直していた）。

## 採らなかった案
- **Rust だけで検査する**: I5 は「検査 script の exit code」と定め、P0-E の command check と同じ契約を別言語の実装で突き合わせたい。Rust の実装は試験の独立 judge に置いた。
- **evidence を課題ごとの秘密にする**: 公開の契約から導けない値は、実 LLM が当て推量でしか通れない（A9 findings D2 の理由）。
- **v1 の raw を v2 で採点し直す**: A9 findings D2 の「採らなかった案」のとおり、数字は書き換えない。

## 旧い仕組みの扱い
- `hidden/expected.json`・`outcome_reached`（sha256 照合）・stub の `--answers`（台本の答えを書く分岐）を消した。互換の二重判定は置かない。
