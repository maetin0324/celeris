# release target 再作成時の削除を最大3回にする

## 事実
P1-H の配送 prepare は、容量上限を超えた target の `rm -rf` が `Directory not empty` を返して停止した。削除中の書き込み元は未確認であり、恒常的な権限エラーとも断定しない。

## 決定
容量超過時の target 削除だけを最大3回試す。成功した時だけ seed の target への置換と開始時刻の記録へ進む。3回失敗したら非ゼロで停止し、再作成用の一時ディレクトリを消す。失敗を無視して古い target でビルドしない。既存の release ロック・scratch lease・パス検査・容量算定は維持する。

試験では rm を関数で差し替え、最初の削除後にファイルが残る場合と恒常的な失敗を決定的に再現する。負荷や実時間の競合を使わず、本番の target は変更しない。
