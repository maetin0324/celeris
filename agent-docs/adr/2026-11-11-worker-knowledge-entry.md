# worker の KB 入口を検索手順にする

日付: 2026-11-11。状態: 採用。

## 根拠と範囲

task 01M75722TSX26Q8PXTG0RCZ72Q の依頼にある operator の観測では、worker 1995 run のうち検索・取得は 61 run（3.1%）。1979 prompt のうち 1650 本に約 57 KB、最大 200 件の題名の索引が入っていた。これは log からの観測であり、新しい受信側の計測による結果ではない。現行実装はマウントごとに索引を列挙するので、広い scope と案件 scope の重なりでも同じページを列挙する。

## 決定

ADR-0047 D2 の worker prompt への索引列挙を廃止し、実効マウントと短い検索手順を出す。task の対象・エラー・設計判断を検索語にし、案件の scope で絞り、検索結果の path を get して本文と出典を確認する。複雑な知識は必要なときに取得する。マウントがあれば索引が空でも手順を出す。

関連ページを自動選別して数件挿入する案は採らない。題名の先頭順には関連性の根拠がなく、この変更では新しい順位付けの推測を増やさない。マウントの配送と PaperQA の比較対象探索に使う KnowledgeContext.index は維持する。廃止するのは通常の前置きの列挙経路と上限定数である。

record の候補は日次整理が検証を通過すると daemon が適用する。人が書いたページの保護などで必要になった判断は人へ回る。「候補はすべて人が確認してから正本に入る」という案内をこの現行経路に合わせる（ADR-0131「付記（2026-10-04、日次整理の自動適用）」、2026-10-27 daily-knowledge-extraction）。

## 検証と残る作業

旧い 200 件列挙の試験は契約廃止により置き換える。新しい試験では、空索引でも入口が出ること、大量の索引と重なるマウントでも題名・本文を展開せず prompt サイズが索引件数に依存しないこと、検索・取得・記録の案内と節の配置を固定する。

この ADR は worker の入口の判断のみ。run ごとの受信側計測・report・curation の統合優先は同じ task の残作業であり、実装前に別途設計する。CoS の常設文脈は task 01M75722QN630BBASEQ759KG4T の範囲である。
