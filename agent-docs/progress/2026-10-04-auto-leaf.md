# PROGRESS — 深さ上限の leaf の自動実行

正本: [ADR-0079 付記](../adr/0079-recursive-task-decomposition.md)「2026-10-04、深さ上限の compound leaf の自動実行と警戒」。

- `auto_leaf=true` を既定にし、深さ上限で子 task にできない compound leaf を判断待ちなしで実行する。
  深さに余裕がある場合の子 task 化は維持する。計画に紐づく gate event の `action=auto_leaf` と理由を保存する。
- compaction/context rollover と continuation の既定上限は各 2。3 回目で該当 leaf を `blocked(decision)` にし、
  既存の `leaf_too_large` 決定を受信箱に表示する。質問に回数・閾値・直近の進捗・leaf の位置を載せる。
- Claude Code の `system/compact_boundary` を検出する。stream の印が無い場合は context 予算切れ・rollover で代用する。
  同じ context の二重計数を防ぎ、兄弟や planner の run は混ぜない。回答後は計数区間を更新し、checkpoint/session から続行する。
- 実行中の compaction 超過は既存のプロセスグループ・コンテナ停止処理で中断し、機械的な checkpoint を保存する。
  カウンタはイベントから復元し、dispatcher の再起動と replay に対応する。`auto_leaf=false` は従来の採用時判断待ちへ戻す。
- 設定例、API/protocol 文書、API/event schema、GUI/web の型を更新した。決定 kind・DB migration は追加していない。

## 試験

fake adapter で次を決定的に検査する（LLM・外部ネットワーク・CPU 焼き負荷なし）。

- 深さ上限の compound leaf が 1 run で完了し、判断待ちを作らない。
- compaction と continuation が閾値未満・同数なら決定を出さない。
- 実行中に 3 回の compaction を出して未完了の future を待つ adapter を中断する。
- stream の無い context 予算切れと通常の continuation がそれぞれ閾値を超えると決定を出す。
- 受信箱に理由・3 選択肢が現れ、続行回答後の dispatcher 再生成でも checkpoint を引き継ぎ、過去の超過で再停止しない。
- 連続する session rollover と、その後の新しい context の再枯渇を別々に数える。
- 閾値 0、continuation 無効時の警戒、replan / withdraw の回答、兄弟の完了、replay の一致。
- `auto_leaf=false` の既存テストで実行前の `leaf_too_large` を維持する。
- adapter の parser は auto/manual の完了境界だけ数え、開始中の status・モデル本文を数えない。
