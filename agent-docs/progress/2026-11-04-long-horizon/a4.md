# A4 統括 CoS の相談・小規模作業（相談は即答、短い読取は run 内、修正は task 委譲）

完了日: 2026-11-04

## 結論
- 人は応じ方を選ばない。daemon が発言ごとに型（相談・読取・委譲）と規則 id を推定し（`task_core::chat::intent::classify`）、prompt の入力の横に hint として置く。LLM は文脈で覆せる。
- 相談は task を作らず返事で答え、短い読取は CoS run の中で shell コマンド `[cos] inline_read_max_commands`（既定 20）回まで許す。超えた 1 回目と、CoS run の LLM CLI・API・subagent の起動で run を止める（worker の `CosInlineBudget`）。
- 修正・長い作業は短命の task を 1 件起票する（既存の `task.create` OP。review と成果統合の経路は変えていない）。統括の run が起票した root が done になると、完了の事実が**元の統括 thread** に置かれ、CoS がそこで要約する。続きの相談は同じ thread で受ける。
- 統括 CoS が自分の提案を案件 CoS へ渡す経路 `chat.proposal_forward`（`POST /api/v1/chat/threads/{t}/proposals`）を Rust/API に足した。監査付きの CoS operation で、案件 thread の `role=system` の入力（`cos_proposal` の記録と固定の接頭辞）になり、`instructed_by` に引くと 422。人の発言の取り次ぎ `chat.relay_forward` は原文のみのまま変えていない。
- 「1 run = 1 turn」「subagent・他 LLM CLI 禁止」「統括 1 窓口と案件ごとの session」は保った。1 依頼 = 1 root の読み方は「作業の依頼」に限った（相談・読取は root にしない）。

## 契約を変えた点（ADR 付記 A4）
- `cos_intent` は TS の領域でなく Rust の純粋関数にした。hint は状態・起票・認可・予算に効かず、TS の領域の追加（migration・runner・bundle・schema の十数か所）に見合わないため。
- 読取の上限は worker 側（claude-code adapter）で数える。CoS の実行器が claude-code 固定のため、codex・acp には入れていない。
- proposal の記録は `author` でなく `cos_proposal.proposed_by = cos:<統括 thread>`（`author` は `role=user` の欄）。
- E2E は対象の crate ごとに置き、下限を 13 件にした。

## 未解決
- 読取の上限は shell の道具（claude-code の `Bash`）の回数で数える。`Read`・`Grep` など shell でない読取の道具と、API の GET の回数は数えていない。1 回の shell に多くの処理を詰めることは防げない（回数の上限で、内容の上限ではない）。
- codex・acp の adapter には上限を入れていない（CoS の実行器は claude-code 固定）。CoS の実行器を広げるなら同じ `CosInlineBudget` を各 adapter の tool_use の観測点に足す。
- 実 LLM での確認（推定を LLM が実際に従う・覆す割合、相談で task 0 になる割合）はしていない。worker の run の規則で LLM を起動できないため、人の手順として次の gate に置く。
- 推定の規則は語の一致で、語の無い依頼（「あれ、いい感じにして」）は相談の既定に倒れる。安全側（task を作らない）だが、委譲の取りこぼしは LLM の判断頼み。

## 次の gate
- 人が本番で統括 CoS に 3 種の発言を送り、task 数・読取の回数・完了の要約の戻り先を確かめる（`celerisctl` と画面の統括スレッド）。
- A5・A7 は `chat.proposal_forward` の `cos_proposal` を authority の `source` に使えない（A7 の「偽の人の指示」）ことを試験で固定する。

## 提案
- hint の規則を実データで直す頻度が高ければ、`cos_intent` を control-ts の領域（`ProposalOnly`）へ移す。
- 読取の上限を API 側（CoS run の credential の GET の回数）でも数えると、harness に依らずに効く。
