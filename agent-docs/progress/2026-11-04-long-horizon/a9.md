  24〜72 時間の実稼働は人の承認が無いので未実施。

## 変更の要点
- 画面: 判定と権限は API が持ち、画面は応答を出すだけ。mode の PUT は今の `revision` と理由を送る。理由が空なら押せない。「有効にする」は
  確認の dialog（起票の許可が同時にできることを書く）を通す。判断の規則は proposal の `explanation.rule_id`、無ければ検証の欄。
- 統合の不具合 1: `POST /projects` の直後の案件は `proposed` で、`active` へ移す API が無い。controller を有効にしても TS が
  `pc/project-not-active`、Rust の検証が `pc/invalid:launch_on_paused` で起票を断り続けた。人が `enabled` に上げる操作で同じ tx の
  中で `active` にした（ADR 付記 A9 の 2）。
- 統合の不具合 2: 作業場所が git でない案件では delivery が `not_git` で見送られ、snapshot の `integrated` が false のままで、
  controller は最初の root の後に `pc/root-in-flight` で止まった。取り込むものが無い見送りを取り込み済みに数え、取り込みが閉じた
  event でも wake を積む（付記 A9 の 3）。git の案件でも、merge の後の評価が次の cron（最大 1 時間）を待たなくなる。
