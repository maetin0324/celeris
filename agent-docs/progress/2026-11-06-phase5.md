## 配送の修理（verify の helper の同梱）

### 原因

本 task の配送で、prepare.log（`/local/celeris/state/releases/.deliveries/01M6QW0ANN9CS5CWHMDP3N6PKF/<sha>/prepare.log`）の verify が
`python3: can't open file '/local/celeris/state/current/scripts/snapshot_db.py'` で落ちた（2026-11-06T17:58:15Z）。
N2 の修正（件名「phase 5: pin verify database snapshot during concurrent writes」）で verify.sh は隣の `snapshot_db.py` を
`$(dirname "${BASH_SOURCE[0]}")/snapshot_db.py` で起こすようになった。一方 release.sh の同梱 loop は `scripts/selfdeploy/*.sh` だけを
`<release>/scripts/` へ写していたため、`snapshot_db.py` が release に入らなかった。prepare.sh は `current/scripts/verify.sh` を起こすので、
本番 current（同梱に `snapshot_db.py` が無い）ではどの配送の verify も同じ所で落ちる。

### 修正

- `scripts/selfdeploy/lib.sh` に `sd_bundle_selfdeploy_scripts <src_dir> <dest_dir>` を足した。src 直下の `*.sh` と `*.py` を `cp -p` で平らに写し、
  `tests/`・`hooks/` など下位 directory は写さない。写した後に `promote.sh`（実行可）・`lib.sh`・`verify.sh`・`snapshot_db.py` を確かめ、無ければ `sd_die` する。
- `scripts/selfdeploy/release.sh` の同梱の節は、手書きの loop をやめてこの関数を `"$BUILD/scripts/selfdeploy" "$STAGE/scripts"` で呼ぶ。
- 試験 `scripts/selfdeploy/tests/bundle_includes_verify_helpers.sh`（release 全体は起こさず、関数を一時 dir に対して呼ぶ。決定的）:
  1. release.sh が同梱に `sd_bundle_selfdeploy_scripts` を使う。
  2. selfdeploy の各 .sh が隣から参照する file（`$(dirname "${BASH_SOURCE[0]}")/<名前>`・`$(cd "$(dirname …)" && pwd)/<名前>`・`$SD_DIR/<名前>`・`$script_dir/<名前>` を source から抽出、10 件）がすべて同梱先にある。
  3. `tests/` を同梱しない。
  4. `snapshot_db.py` の無い source では exit 1 で `snapshot_db.py is missing` を出す。
