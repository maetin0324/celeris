## 何を直したか（提出時の HEAD、基準は `git merge-base HEAD main`）
- `driver.py`: `collect_usage` が cache 欄の欠落（`cache_missing`）と `cost_usd` の欠測（`usd_missing`）を数え、1 件でもあれば
  tokens・cache_tokens・usd を null にする。facts に `usage.usd`・`quota_missing: not_measured`・実測の `events_append_only` と
  `events_checked`・`cos_launch_rejected`・`cos_ops_rejected`・`cos_run_failures` を書く。ops の記録に `harness_label`。一時 KB に
  `config/skills/cos-operator`・`cos-inbox-triage` を写す。stub の config に `[budget_rates."model-1"]`。
- `pilot_gate.py`（新規）: `check-approval`（承認の記録の検査）と `judge`（測定の契約の判定、`pilot-gate.json`・`pilot-facts.json`）。
- `long-horizon-pilot-llm.sh`: 環境変数 `LONG_HORIZON_PILOT_LLM_APPROVED` を消し、`--approval <json>` を必須にした。空の `--cos-route`
  を断る。daemon の USD 予算は承認の `max_usd`、wall の既定は承認の `max_wall_secs`。採点の後に judge。`--harness config` で gate が
  pass でなければ exit 3。
- `stub_harness.py`: done・question に固定の usage を付ける（daemon の USD 予算が stub の run も数えられる）。
- `pc_rollout.py`: G7 は judge の出力（`schema` = `celeris.long-horizon-pilot-gate/1`）だけを受ける。stub の facts は pending、
  形の違う JSON は fail。
- `test-affected.sh`: `scripts/dev/long-horizon-pilot/` の変更で単体試験 3 本を走らせる。
- `test-long-horizon-pilot.sh`: 承認の記録が無い・期限切れなら exit 2 になることを確かめる。gate の単体試験と、config-stub の
  `pilot-facts.json` が G7 を主張しない（`pending`・`cos_usage_null` null）ことを確かめる。
- 文書: `docs/ops/project-controller.md` の実 LLM pilot の節、runbook の N1 の手順 3。
