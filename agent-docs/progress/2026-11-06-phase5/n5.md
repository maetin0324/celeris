# N5 証跡の条件と再達成・GC 最大 ID の DB 不変条件

## 変更
- `phase 5: enforce roadmap evidence freshness and retention ID guards` — 起票時の承認済み Roadmap の版を INSERT trigger で固定する。人・CoS の root は起票時と現在の acceptance・checks、および実際の command を照合する。記録の無い旧 root は根拠にしない。
- 再達成では新しい root を evidence に持つ reached を追記する。同じ版・同じ根拠の controller の再適用は同じ event の参照を返す。人の状態操作・root の対応付け・補足理由は従来どおり追記する。
- 検証後の改版・root の reopen を承認版と既存の案件ごとの root event mark の CAS で拒む。API の主体と human_epoch の門は維持する。
- migration 0118 は GC の 3 表の最大 ID の DELETE を permit の有無によらず拒む。既存の GC 選択・archive・監査は維持する。
- 旧 schema fixture は 0118 の追加物も取り除く。wake の欠落を再現する fixture は別案件の消費済み最大 ID を残し、cursor・cron の検証を維持する。
- 設計は [N5 ADR](../../adr/2026-11-06-n5-evidence-integrity.md)。P0-B・P4-B・P4-D の旧判断に改定への参照を追加した。

## 本番への移行
通常の release で schema 118 を適用する。本番の操作は行っていない。人・CoS の旧 root で起票時の承認版の記録が無いものは、Roadmap の到達の根拠にならないため、新しい root の実行が必要になる。controller の既存の起票 metadata の digest は引き続き使う。
