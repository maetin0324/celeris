## Task の受け入れ条件と根拠
試験の件数は各 unit の記録（その unit の提出時の HEAD で実行）による。closeout では試験を走らせ直していない（Rust の変更が無いので `test-affected.sh` の対象は無い）。
- 0. 規則正本・配布経路から planner/worker/reviewer に届き、`CLAUDE.md` の写しを他 repo に置いていない
  - 汎用規約の正本は `crates/task-worker/src/change_rules/generic.md` の 1 file で、binary に埋め込む。`claude_code::prompt` の `prompt_header` から全 run kind（execute・plan・replan・execution plan・review）・全 harness（Claude Code・Codex・Pi・ACP）に 1 回入る。repo 固有の必須規則は従来どおり `CLAUDE.md`（`required_rules`）で、2 つは互いに写さない。
  - 試験: `change_rules_` 16 件（`change_rules_generic_reaches_{claude_code,codex,pi,acp}_…`・`change_rules_generic_once_in_every_run_kind`・`change_rules_generic_and_required_rules_do_not_copy_each_other`・`change_rules_review_kind_descriptions_are_not_copied` など。[prompts.md](2026-11-07-health-v2-g2/prompts.md)）。repo 固有の review 方針は base 側の `--print-review-policy` で読み（`test_health_review_` 19 件、[review-policy-cli.md](2026-11-07-health-v2-g2/dispatch/review-policy-cli.md)）、planner の context に渡す（`health_review_policy_absent_`・`health_review_policy_timeout_` など、[policy-load.md](2026-11-07-health-v2-g2/dispatch/policy-load.md)）。
- 1. review verdict が構造化され、客観的な規約違反と設計上の助言が区別される
  - `ReviewOutput.health` の `HealthFindingOut { kind（固定 7 種）, severity: blocking | advisory, path, reason, repair }`。blocking は不合格にして局所修復（`removal_missing`・`test_change_unjustified` の `repair.scope = "local"`）か replan に写し、advisory は合否に使わず記録と次の run の prior にだけ載せる。health を渡した review で verdict が無い・壊れていれば不合格（I7）。
  - 試験: `health_protocol_` 6 件（[protocol.md](2026-11-07-health-v2-g2/protocol.md)）、`health_review_verdict_` 8 件（[health-verdict.md](2026-11-07-health-v2-g2/dispatch/health-verdict.md)）、`change_rules_review_` 5 件（[prompts-review.md](2026-11-07-health-v2-g2/prompts-review.md)）。
- 2. small low-risk 変更は既存 review に統合され、高 risk 変更だけ設計 review が要求される
  - risk は `task_core::design_review::assess_risk` が決定的に判定する（none < low < unknown < high）。low・none の計画は追加の run なしに採用し、final review に health 文脈を足すだけ。high・unknown の計画だけ採用の前に reviewer run で設計 review する。
  - 試験: `health_review_scenario_normal_change`・`health_review_scenario_high_risk_change`・`health_review_scenario_real_cli`（[scenario.md](2026-11-07-health-v2-g2/dispatch/scenario.md)）、`health_review_design_gate_` 8 件・`health_review_design_verdict_` 6 件、`crates/task-core/src/design_review/tests.rs` の 9 件。task-dispatch の `health_review_` は 68 件（[dispatch.md](2026-11-07-health-v2-g2/dispatch.md)）。

## 未解決事項
- 設計 review の run の reviewer prompt が無い。dispatcher は高 risk の計画で `ReviewRequest.design`（brief・計画の要約・risk・方針）を渡して reviewer run を起こすが、task-worker の `build_review_prompt` と `change_rules::review` に `ReviewRequest.design` を描く節も、`review.json` の `design`（`DesignVerdictOut`）の書き方を指示する文も無い（`grep -rn '\.design\b' crates/task-worker/src` で protocol 以外に参照が無い）。本物の reviewer は `design` を書かないので、dispatcher は「review.json に design が無い」を不合格に数え、1 回目の不合格で planner を再試行させ、不合格が 2 回（`MAX_DESIGN_REVIEW_FAILURES`）続くと計画を採用して `PlanGate`（人の承認）に回す。fail closed で合格はしないが、高 risk の計画は毎回人の判断待ちになる。流れ全体の試験は偽の reviewer が `design` を直接書くので、この穴を検出しない。dispatch task は prompt を prompts task の範囲とし、prompts task は protocol の型が無いとして作らなかった（[prompts.md](2026-11-07-health-v2-g2/prompts.md) の未解決）。
- ADR (7) の撤去のうち D7.1（reviewer prompt の「Commit references in progress files and reports」節、`prompt.rs` に残る）・D7.2（health の無い review の Result 節は旧い形のまま）・D7.4（`PLANNER_CHECK_GUIDANCE` の `CLAUDE.md` と同じ文、`PRODUCTION_HOST_PLANNER_GUIDANCE`）は未実装。G2 の計画に U6 の unit が無かった。D7.3 は guideline と review-policy-cli で済んだ。

- 設計 review の reviewer prompt を足す task を起こす: `change_rules::review` に `ReviewRequest.design` の節（brief・計画の要約・risk の理由・方針の class と不変条件）と、Result 節に `design: {pass, findings}` の形を足す。偽の reviewer でなく実際の prompt の文面に `design` の指示があることを確かめる試験（`change_rules_review_design_` 系）を置く。それまで高 risk の計画は人の承認を経る。

- generic.md の規約 7〜9 の扱い（kind を足すか advisory に限るか）を決める。kind を足すなら D5.1 の表・`HealthFindingKind`・generic.md を同じ変更で変える。
