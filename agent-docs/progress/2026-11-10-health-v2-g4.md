## ADR の期待を契約に合わせた訂正
- ADR の初版は、`dup.*` が fail 級（exit 1）になり、`deps.violation` が層の宣言なしでも動く前提で書いていた。契約 [ADR 2026-11-07 repo health の契約](../adr/2026-11-07-repo-health-contract.md) では、`dup.*` は候補（candidate=true・severity warning 以下）で verdict に影響せず、review に渡る材料になる。`deps.violation` は層の宣言が無ければ `not_applicable`。py-detect の v1 の試験はこの食い違いで 12 件落ちた。
- 検査器は契約どおりに動いているので、検査器は変えず ADR と試験を直した（ADR の「付記（2026-11-10、unit py-detect）」）。dup-contract・dup-state の期待は「候補が 1 件、exit 0・verdict pass、final review の材料に入る」。fail 級の土台（policy の弱化 5 種・history-smuggle・(e)(g)(h) の Fail と repair、class `health:deps.violation`）は、fixture の base の profile が層を宣言した dep-inversion に移した。
- 実装とのその他の食い違い（variant の追加、flag の実名、rust の `deps.cycle`、measure の回数と file 名など）は ADR の「付記（2026-11-11、unit record）」。

## 解決した欠け G4-S1
- 欠け: `Check::Reviewer` のある task で決定的な条件が落ちると、review は reviewer run を起こさず reviewer の項目を「not evaluated: a deterministic check failed」の不合格にする。`Dispatcher::try_review_repair` がこの項目も分類に入れたので、health の Fail も fmt の不合格も Substantive になり、repair に回らず `review_fail` になった。rs-stale が見つけた。
- 直し: unit fix-s1。`crates/task-dispatch/src/dispatcher/review_verdict.rs` の `try_review_repair` が、決定的な不合格があるとき reason が `review::REVIEWER_NOT_EVALUATED_REASON`（`crates/task-dispatch/src/review.rs`）の項目を分類から外す。[ADR-0072](../adr/0072-task-execution-decomposition.md) の付記 G4-S1。`task_core::classify_review_failure` は変えていない。
- 試験: fix-s1 の `review_repair_not_evaluated_reviewer_does_not_block_a_health_repair`・`review_repair_not_evaluated_reviewer_does_not_block_a_format_repair`・`review_repair_not_evaluated_only_skips_the_not_evaluated_reason`。rs-stale の `health_generic_reviewer_reuse_health_fail_routes_to_repair` は `should_panic` を外して合格する（class `health:deps.violation` だけの review の repair の後に done）。

## 解決した欠け G4-R1

## 段 hardening の統合を止めた試験
### deflake-ws（直した）
