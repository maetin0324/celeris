## 提案

- record-fix の提案（D7 の試験の無い部分を試験にする unit、cex-lease の未解決の反例の確認）は、計画 v10 の段 pin-rest と fix-promote で済んだ。
- 上の「D7 の表の外」の窓は、各 unit の提案のとおり別の変更で扱う: `finish_worker_result_with` の WU の書き込みを `work_units_apply` の 1 回に
  まとめる（fix-promote）、reviewer run の判定の適用を `runs` 行の照合と同じ writer transaction で書く store の口にする（cex-race。store の高 risk の
  class なので設計 brief と設計 review を通す）、v2 の計画で WU の done の直後に止める試験の hook（cex-tick）。
- fix-integ の提案: `ready_promotions` を `crate::execution_scheduler` へ移す。`on_integration_finished` の stale discard が統合 WU を running のまま残す件を決める。
- fix-cred の提案（`ExecutionCoordination` の `credential_held` を消し、待ちの重複の判断を store の開いた wait にする）は cred-cache が済ませた。
- slices-check の write_set の正規表現 `[a-z_/]+` は数字を含む試験の file 名（`cos_live_fix_d4.rs`・`credential_e2e.rs`）に当たらない。後の slice では `[a-z0-9_/]+` にする（slices.json は policy に近いので operator が判断する）。
- 「policy の撤去」節の task (i)・(ii) を operator が起こす。
