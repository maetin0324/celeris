## base-fn 再提出（check 不合格の直し）
- 前回の不合格の原因: (1) `health_review.rs` の mod 宣言が範囲 check の外だった。(2) `cargo test -p task-dispatch --lib health_review` は同一 process の同梱検査器（process 全体の設定）で 11 件落ちる。今回の変更とは無関係で、`cargo nextest`（試験ごとに process）では 134 件通る。plan の check は nextest か個別実行にするのが妥当（提案）。
- 直し: `target_base` を `health_review/gate.rs` の子 module（`#[path]`）にし、`health_review.rs`・`dispatcher/` を変えない。`dispatcher/` に置くと repo health の size.responsibility-growth が悪化する（`#[path]` で単位に数えられる）。
- 提出時の HEAD で実行: `cargo clippy --workspace -- -D warnings` 0、`cargo fmt --all -- --check` 0、`cargo nextest run -p task-dispatch --lib health_review` 134 通過、`bash scripts/dev/test-affected.sh` 3814 通過・repo-health pass。
