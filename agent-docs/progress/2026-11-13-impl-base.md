## WU base-tests（8 形の決定的な試験）
- `crates/task-dispatch/src/health_review/target_base_tests.rs`（`check_item.rs` の子 module。`check_item.rs` に mod 宣言の 3 行だけ足した）。git の実 repo と base の commit に置いた stub の検査器で、時計・負荷・外部ネットワークに依らない。8 件（prefix `health_base_`）。WU の check と段の統合の両方を同じ形で通す（`phase` の false/true）。
  1. `clean_merge_of_target_passes`: target を衝突なく merge → 合格。base は親が start・T の merge commit。同じ head を base = start で評価すると落ちる。K5（同じ入力で同じ sha）も確認。
  2. `resolved_conflict_passes_and_runs_against_target`: 衝突を解いた merge → 合格。検査器は 2 回（1 回目 base は衝突の印を含む commit、2 回目 base = T）。
  3. `conflict_resolution_is_judged_against_target`: 解かない（印のまま）・T より大きい解き方 → 2 回目で落ちる。target 側の内容で解けば合格。検査器の dir の file の衝突は Unavailable。
  4. `without_intake_keeps_start`: 取り込まない WU・段、`Ok(None)` は base = start。
  5. `merge_commit_additions_fail`: merge commit に足した fail 級・merge の後の commit・衝突の解き方に混ぜた fail 級が落ちる。
  6. `phase_fast_forward_intake_and_worker_policy_change`: 段の ff の取り込みは base = T。worker の policy の変更は残る（旧 5 件の不変条件を移した）。
  7. `unavailable_inputs_do_not_pass`: target の Err・ref なし・start Err・head 不明・criss-cross・検査器の file の衝突は Error で、検査器を起こさない。
  8. `candidate_cannot_weaken_policy_or_checker`: merge commit で検査器・policy を弱めても base 側の版が動き、`policy.changed` で落ちる（I3）。
- 各試験の doc comment に守る不変条件と、既存の試験で検出できない理由を書いた。
- 試験を書いて分かったこと（本番コードの不備ではない）: 衝突は start（Task の branch）と T が同じ file を変えたときに base の merge で起きる。2 回目（base = T）は start 側の変更も差分に数えるので、start が policy の file を変えていれば衝突が無くても 2 回目で `policy.changed` になる（ADR D3.4 の設計どおり）。`target_base.rs` は変更していない。
- 証拠（提出時の HEAD で実行）: `cargo nextest run -p task-dispatch -E 'test(health_base_)'` 8 件合格。`cargo nextest run -p task-dispatch --lib -E 'test(health_review) | test(health_base_)'` 142 件合格。`cargo fmt --all -- --check` 0、`cargo clippy --workspace -- -D warnings` 0、`bash scripts/dev/test-affected.sh` 0。`cargo clippy --all-targets` は task-core の test で既存の 4 件（useless_conversion 等）が落ちる（本 WU と無関係で、受け入れの形の clippy ではない）。
