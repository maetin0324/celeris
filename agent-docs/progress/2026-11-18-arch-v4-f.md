## 決定の要約（ADR の D1〜D7）
- D1: `POST /knowledge/inbox` の HTTP の pin は `SqliteStore::write_tx` で書く。`rusqlite::Connection::open` と自前の Immediate の transaction を消す。
- D2: 受信箱の provenance は新しい `SqliteStore::attachment_provenance`（`with_read_conn`）で読む。`open_attachment_index` を消し、`provenance_for_owner` は
  task-core の crate の中に縮める。`SqliteStore` の `pub` method は 1 増える。
- D3: `record_op` を D の付記の形（共有の `record_candidate`・`pin_candidate_tx`・`discard_candidate`、HTTP は `write_tx`、CoS は `reject`・`apply_checked`）へ移す。
- D4: task-ops の `apply_project_action` を closure ごと消す。task-ops は `plan_project_action`・`apply_project_change_tx`（`&rusqlite::Transaction<'_>`）・
  結果の組み立てだけを持つ。HTTP は `write_tx` の中で `apply_project_change_tx` の後に `HumanEpoch::bump_tx`、CoS は `cos/ops/projects.rs` で `reject`・`apply` を直接呼ぶ。
  `project_action_op` を消す。
- D5〜D7: 範囲外と理由、試験（旧コードで固定する契約試験 4 つを含む）と撤去の条件、旧い経路を書いた ADR 3 本は実装の unit が付記で書き換える。
