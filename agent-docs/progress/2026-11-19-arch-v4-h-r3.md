## 提案

- `review_verdict.rs` を次の task で実装する条件（ADR から写す）: `on_review_finished` の (1) review lock → (2) 部長の session の記録 → (3) runs 行の確認 →
  (4) 計画の開き直しの確認 → (5) 判定の反映、の順序を固定する試験（反例 4 本に加え、(3) と (4) を入れ替えると落ちる試験）が先にあること、
  1 回化で減る出現が 3 以上あること、変える行が 2 つの `events_for`（reviewer の基盤の失敗と再投入の数）の分岐の中に収まること。
- `work_units.rs` を次の task で実装する条件（ADR から写す）: 遷移の純粋関数の置き場（既存の `task_core` の WorkUnit の module か `ExecutionCoordination`）を
  ADR で決めること、本体の行（いま 2053、閾値 2000）を減らす方向だけで変えること、lease・restart・並列 WU の反例 4 本と `structure_guard_*` が通ること、
  分母を増やす分は成果に数えないと先に書くこと。
- `tree_units.rs` の `reconcile_tree_units` と `handle_child_infra_failure` に同じ並び（`answered_decisions` → `build_child_task`）がある。
  「同じ並びが 2 か所以上あり、helper の後の総数が減るなら純減に数える」などの規則を先に決めれば、同じ file の private 関数 1 つで store −2・config −2 が見込める。
- `dispatch_run.rs` の `apply_plan_invalid_atomic` と `decision_self_hold` は同じ流れで同じ決定の一覧を読む。まとめるには呼び出し元から見た引数を変える決定が要る。
