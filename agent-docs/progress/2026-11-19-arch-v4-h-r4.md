## 提案

- `ChatAttachmentStore` 自体の書き込みの接続（`open_with_flags(.., READ_WRITE)`・固定の `busy_timeout` 10 秒）を `SqliteStore` に載せる案
  （ADR §6 の案 B）を別の task で決める。大きな file の upload の間に store の書き込みの `Mutex` を持ち続けないよう、blob の rename と
  行の確定の手順と lock の範囲を設計する必要がある。決めるまでは `busy_timeout` を store の設定に揃える小さな変更も候補になる。
- `state.rs` の `measure_journal_mode` を `SqliteStore` の読み取り（`PRAGMA journal_mode`）へ移すと、task-api の `Connection::open` が 0 になる。
- `capability-map.json` の `cos-inbox-triage-operations-audit` の owner と根拠 path を `crates/task-core/src/cos_inbox.rs`・`chat/triage.rs`
  に直す policy の変更を人が起票する。直した後なら `terminal_conflict` を `cos/inbox.rs` に戻し、`cos/triage_view.rs` を消せる
  （[triage.md](2026-11-19-arch-v4-h-r4/triage.md) §5）。
- task-core の `chat` module は repo health の `size.responsibility-growth` の閾値 8000 に近い（R4 の後 7944）。`chat::triage` の読み取り
  （`cos_triage_cursor`・`cos_triage_route_version`）を `feed_cursor_get` へ寄せる整理を別の task で行う。
