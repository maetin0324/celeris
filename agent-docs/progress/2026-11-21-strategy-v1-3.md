## 結論

- 人は案件の CoS chat で、発言ごとに議論（discuss）・案（propose）・実行（execute）を選んで送れる。省略と execute は今と同じ挙動。
- discuss と propose の run が `/cos/operations` の登録済み 111 action と `/cos/inbox/{i}/resolve` を呼ぶと、API が 403 `discussion_mode_forbidden` で拒否し、
  拒否を監査に残す。副作用が 0 であることを負の試験で確かめた（prompt だけに頼っていない）。
- propose の案は返事の workspace file `strategy/<id>/v<n>.json`（子 2 の `celeris.strategy/1`、`decision_state` は discussion か proposed）として添付し、
  approved の案・discuss の run の案・同じ版の別の中身は添付しない。
- 人は自分の発言を編集・撤回でき、前の本文は `chat_events` の `message_revised` に残る。要約・案の引用は `{thread_id, message_id, revision, sha256}` を持ち、
  元の発言の編集・撤回で失効する（要約の検査、子 2 の `strategy_gate`、GET・SSE、web の表示）。
- 新しい DB 表・migration・Manager・trait・Agent サービスは足していない。production の行は +2,697（Rust +1,858）の純増で、理由は下の LoC の節。
- 親の目的への寄与で確認済みなのは、改善 B（引用と revision 付きの共有）と observability（画面の mode・主体・引用の状態）の土台だけ。改善 A・C・D は推定か未確認。
