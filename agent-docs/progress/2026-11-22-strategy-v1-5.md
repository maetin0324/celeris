## 結論

- CoS が `strategy` を付けて起票する限り、実行の入口（`/cos/operations` の `task.create` の gate）は、`selected` の無い版（実験段階）から大きな計画（compound）を通さない。
  通すのは open の候補ごとに 1 件の atomic の識別実験（最大 3 件）だけである。`selected` のある版の compound は、`task.create` の時点で前の版の実験 task が 1 件以上あり、
  すべて終端で、すべて版の証拠に参照され、文書の task が Critic を通って done のときだけ通る。却下した候補は消せず、選べず、起票できない。
- 訂正（adr-scope の WorkUnit、final review の条件 4）: 前の版のこの節は、選ぶ版を実験の結果を読んでから書いたことまで gate が保証すると読めた。gate は版を書いた時刻を見ないので、
  選ぶ版を実験の結果より先に書くことは gate では止めない（走っている実験 task を先に参照して `selected` を書いた版も、実験が終われば通る）。
  確かめるのは人の承認と Critic の C4 だけである（「未確認の事項」と「提案」）。
- Critic は新しい Agent ではない。戦略の文書を作った task の final review で、既存の reviewer の 1 回の run が固定の基準 C1〜C5 で判定する（暗黙の条件 `strategy_critic`）。
  dispatcher は reviewer の出力の形だけを確かめ、LLM を呼ばない。
- 子 0 の E-mid（アーキv4 で子 A〜C が done の時点）の記録だけを使う shadow の試験で、初回の子 A〜H の compound は 422 で止まり、識別実験 3 件だけが通った。
  戦略を選ぶまでに起票した task は 5 件（文書の task 2・実験 3）で、アーキv4 の実際の初回の起票は 8 件だった。再評価の版は、却下した候補に戻ると 422、失敗した実験の参照を落とすと 422 で止まった。
- strategy の無い `task.create`（明確なバグ修正など）と、戦略の文書の無い task の reviewer の prompt・`request.json`・reviewer run の数は base と同じ（回帰の試験 5 件）。
- 新しい試験は 5 系統 42 件で、提出時の HEAD で全部 pass した。production は +1,142 行（全部 Rust）、own_total_with_tests は +4,324 行の純増。理由は「LoC」の節。
- 実際の LLM の CoS と Critic で shadow を走らせていない。本番でも観測していない。どちらも未確認。release と本番昇格、skill の本番 KB への反映は人が行う（「本番への移行」）。
